# Crate Playlist Builder

Browse your Apple Music library as a collapsible **Artist → Album → Song** tree, tick what you want, and build a playlist from it.

Live at **https://crate.ramakocherlakota.net**

## How it works

The screen is a playlist list on the left and the open playlist on the right: rename it in place, search or filter the tree (**All songs / In playlist / Changes**), and tick songs. The library chip at the top holds loading a newer library file, won't-sync warnings and forgetting the library; **View** holds grouping and sort options; **Review & apply** shows every change and the way to apply it on this device; **Help** has the instructions. On a phone the playlist list and the playlist being edited are separate screens (with a back button), and a bar at the bottom shows the change count (tap it to list the changes) and Review & apply.

1. In Music on a Mac: **File → Library → Export Library…** and save the XML.
2. Load it on the page (or drag it on). Everything runs in your browser; nothing is uploaded. The library, your edits and your view (search, toggles, open folders) are remembered in this browser (IndexedDB and localStorage) until you choose **Forget this library**.
3. Tick artists, albums or songs. Open any number of existing playlists (or start new ones) and switch between them; each keeps its own changes. Press ♪ next to a song to hear Apple's 30-second preview (looked up through the public iTunes Search API).
4. Copy, download or share (AirDrop from a phone, where Share is the main button) the generated AppleScript and run it in Script Editor on your Mac. One script covers every playlist you changed. It finds each song by its persistent ID, so it works for streaming Apple Music songs as well as local files.

### Keeping the phone in sync

With **Afterwards, save an updated Library.xml to iCloud Drive › Crate** ticked (the default), each script finishes by writing the library (songs and playlists) to `iCloud Drive/Crate/Library.xml` in the same format as Music's own export, since Music has no scriptable Export Library. Load that file in Crate on the phone: what the script applied shows as done, and edits not yet run stay pending.

The playlists themselves reach the phone's Music app through **Sync Library** (Apple Music or iTunes Match) automatically, or, without a subscription, by syncing the iPhone with the Mac in Finder (by cable, or over Wi-Fi once **Show this iPhone when on Wi-Fi** is ticked).

The export also records each song's iCloud status. Crate marks songs iCloud won't store (duplicate, ineligible and so on) with **won't sync**, and warns in the library menu, the playlist list and Review & apply when a playlist contains one, because such a playlist won't reach your other devices.

### Adding songs from the phone with Shortcuts

**Add with Shortcuts** runs a one-time-built shortcut, `Crate Add Songs`, on the device itself, covering every playlist with additions in one run: it finds each song by title, artist and album and adds it to its playlist (creating new playlists as needed), then returns to Crate with its version and any songs it couldn't find, which stay pending. If the shortcut's version is older than Crate expects (or it stops with an error), Crate links to the setup guide to reinstall it; bump `VERSION` in `tools/make_shortcut.py` and `SHORTCUT_VERSION` in `site/index.html` together when the shortcut changes. With Sync Library on, iCloud carries the change to the Mac. Shortcuts can't remove songs or rename playlists, so only the additions are sent (to the playlist's current name in Music); removals and a rename stay pending for the Mac script or doing by hand in Music. The easiest install is the iCloud link https://www.icloud.com/shortcuts/a8967f8f95804cb5aa334c61a6522f19 (a snapshot, so each new version needs a fresh link in `site/index.html` and `site/shortcut-setup.html`). Setup steps are in the app under **Set up the Crate shortcut**, with a detailed walkthrough at [`site/shortcut-setup.html`](site/shortcut-setup.html) (https://crate.ramakocherlakota.net/shortcut-setup.html). The guide also offers a ready-made `site/crate-add-songs-unsigned.shortcut`, generated by [`tools/make_shortcut.py`](tools/make_shortcut.py); sign it on a Mac with `shortcuts sign --mode anyone --input crate-add-songs-unsigned.shortcut --output "Crate Add Songs.shortcut"` and double-click the result to import it.

### Changes, not rewrites

The script applies only what you changed: unticked songs are removed, newly ticked songs are added at the end (existing order is kept), and a renamed playlist is renamed in Music. Anything already done is skipped, so scripts made on different devices can be run in any order, and running one twice is harmless. **Undo** (or ⌘Z) reverses the last change: ticks, renames, closing a playlist or Mark as applied. Loading a newer library keeps your unapplied edits on top of any changes made elsewhere. **Review & apply** lists exactly which songs each playlist will gain or lose (with a per-song Undo), and the tree's **Changes** filter highlights them in place. After exporting a script, **Mark as applied** resets the change counts so the next script only carries newer edits.

The app is [`site/index.html`](site/index.html), plus the Shortcuts setup guide ([`site/shortcut-setup.html`](site/shortcut-setup.html)).

## Hosting

`infra/site.yml` is a CloudFormation stack that creates:

- a private S3 bucket
- a CloudFront distribution (HTTPS, reads the bucket through Origin Access Control)
- an ACM certificate for `crate.ramakocherlakota.net`, validated automatically through Route 53
- Route 53 A/AAAA alias records pointing at CloudFront
- an IAM role that GitHub Actions on `main` assumes via OIDC (no stored AWS keys)

### One-time setup

```sh
# Find the hosted zone ID for ramakocherlakota.net
aws route53 list-hosted-zones-by-name --dns-name ramakocherlakota.net \
  --query 'HostedZones[0].Id' --output text      # -> /hostedzone/Z123... (use the Z123... part)

# Create the stack (must be us-east-1). Takes ~5-15 minutes while the cert validates
# and CloudFront deploys. If your account already has the GitHub OIDC provider,
# add CreateOidcProvider=false.
aws cloudformation deploy --region us-east-1 \
  --stack-name crate-playlist-builder \
  --template-file infra/site.yml \
  --capabilities CAPABILITY_IAM \
  --parameter-overrides HostedZoneId=Z123...

# Read the outputs
aws cloudformation describe-stacks --region us-east-1 --stack-name crate-playlist-builder \
  --query 'Stacks[0].Outputs' --output table
```

Then set three **repository variables** (Settings → Secrets and variables → Actions → Variables), or with the GitHub CLI:

```sh
gh variable set AWS_ROLE_ARN --body "<DeployRoleArn>"
gh variable set S3_BUCKET --body "<BucketName>"
gh variable set CLOUDFRONT_DISTRIBUTION_ID --body "<DistributionId>"
```

### Deploys

Every push to `main` that touches `site/` runs `.github/workflows/deploy.yml`, which syncs `site/` to the bucket and invalidates the CloudFront cache. You can also run it by hand from the Actions tab.
